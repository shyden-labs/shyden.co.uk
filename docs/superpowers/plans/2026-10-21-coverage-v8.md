# Coverage measured by @vitest/coverage-v8 (#896) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every Vitest suite can run under V8 coverage. The reports merge into one, and a verdict lists every changed line and branch that no test ran, or that no report measured. CI prints it on every pull request; it does not gate yet (#902 does, after #899-#901).

**Architecture:** A separate `vitest.coverage.config.ts` reuses the unit config, minus exactly the two unit judges (own CPU, file load). The guards, simulation and integration configs gain a coverage block that is inert without `--coverage`. Two plain scripts with pure, exported cores: `scripts/coverage-merge.mjs` (Istanbul JSON maps → one map + the tree it measured) and `scripts/coverage-changed.mjs` (`git diff` + merged map → verdict).

**Tech Stack:** Vitest 5.0.3, `@vitest/coverage-v8` 5.0.3 (MIT, installed in this worktree, uncommitted), Node 26, GitHub Actions.

**Spec:** issue #896 (as re-scoped 2026-10-21), plus #899-#902 for what is out of scope.

## Global Constraints

- `@vitest/coverage-v8` is pinned exactly to the vitest version `package-lock.json` resolves (5.0.3).
- `npm run test:unit` (the 1 s step) never runs coverage and keeps both judges; no limit is raised anywhere: `testTimeout`/`hookTimeout` stay at 1_000 in the coverage config (hook `unit-limit-never-raised.py`).
- Unit tests start no process and open no socket: every git call lives in a script's `main()`, tested in `tests/integration/`.
- One test per case (meta-guard `one-test-per-case`); every absence search goes through `searched(...)` with a `floorBreach(...)` in its own test.
- Measured code: `.ts .tsx .mts .cts .js .mjs .cjs` under `src/`, `scripts/`, `functions/`, and the helpers directly under `tests/` (`tests/*.ts`), excluding `*.d.ts`, `*.test.ts`, `*.spec.ts`. `.astro` files are not measurable by Vitest: they are "unmeasured" until #899 measures `astro build`.
- Every commit message carries `Gaps checked:`; commits are made by hand, never from a script.
- Any task that adds a file a meta-guard derives (a config, a test, a script) runs `npm run floors:record -- --unit-suite` before its commit; the full CI record before the PR folds the rest (#895's hand fold).
- The laptop runs only the unit suite (with or without coverage), formatters, linters and typecheck; guards, simulation and integration coverage run in CI.
- `coverage/` is git-ignored.

## Review Focus

1. A renamed file (`rename from/to` in the diff): the verdict judges the NEW path's added lines only; test in Task 3.
2. A deleted file or deleted lines only: nothing to judge, no crash; test in Task 3.
3. A changed line inside a multi-line statement whose count is 0: counted unrun even though the statement starts on an earlier line; test in Task 3.
4. A report written for another tree (stale) or missing: the verdict exits 2 naming why, never "0 unrun"; tests in Task 3.
5. Two suites' maps for one file whose ids differ (each suite transforms on its own): the merge keys statements, functions and branch arms by source location (`line:col-line:col`), never by id, so the same code merges whatever its ids; test in Task 2.

### Task 2: Merge the suites' reports

**Files:** Create `scripts/coverage-merge.mjs`; Test `tests/unit/coverage-merge.test.ts`; Integration `tests/integration/coverage-merge-script.test.ts`.

**Interfaces:**
- Produces: `mergeMaps(maps: readonly Record<string, FileCoverage>[], root: string): { merged: Record<string, LocatedCoverage> } | { refusal: string }`. Keys are repo-relative POSIX paths. `FileCoverage` is Istanbul's shape (`statementMap, s, branchMap, b, fnMap, f`); `LocatedCoverage = { statements: Map<string, { start: number, end: number, count: number }>, branches: Map<string, { start: number, end: number, count: number }> }`, keyed by `line:col-line:col` of the statement or branch arm, with counts summed across maps.
- `main()`: reads `coverage/{unit,simulation,integration}/coverage-final.json` (guards left out after PR #903's first run: the duplication guard took 64 s under coverage against its 25 s limit), refuses if ANY is missing (naming it), writes `coverage/merged/coverage-final.json` and `coverage/merged/tree.txt` = `git rev-parse HEAD^{tree}`.

### Task 3: The changed-line verdict

**Files:** Create `scripts/coverage-changed.mjs`; Test `tests/unit/coverage-changed.test.ts`; Integration `tests/integration/coverage-changed-script.test.ts`.

**Interfaces:**
- Produces: `changedLines(diff: string): Map<string, ReadonlySet<number>>` from `git diff --unified=0 --no-color --find-renames <base>...HEAD`, keyed by the new path; `judge(changed, merged, isMeasurable: (path) => boolean): { unrun: Finding[], unmeasured: Finding[], judged: number }` with `Finding = { file: string, line: number, kind: 'line' | 'branch' }`; `render(verdict): string` (markdown for the job summary).
- `main(argv)`: `--report-only` exits 0 whatever the verdict, but exits 2 on a missing or stale report (`tree.txt` ≠ `git rev-parse HEAD^{tree}`), a missing base, or an unreadable diff, naming which. Without the flag (#902) it exits 1 on any unrun or unmeasured finding.

- [ ] **Step 1: Failing unit tests**, one per case:
  - `changedLines`: added lines of a modified file; a new file (`--- /dev/null`); a rename keyed by the new path (Review Focus 1); a deleted file yields no key (Review Focus 2); a hunk `@@ -3,0 +4,2 @@` gives lines 4 and 5; a hunk with `+c,0` gives nothing; a binary file is skipped; a path with a space survives.
  - `judge` (over `LocatedCoverage`): a changed line inside a statement with count 0 → unrun `line`, including a line in the middle of a multi-line statement (Review Focus 3); the same with count 1 → not listed; a branch whose arm covering the line has count 0 → unrun `branch`; a changed comment line (no statement) → neither listed nor judged; a changed measurable file absent from the map → every changed line `unmeasured`; a file the report includes with every count 0 (page scripts, workerd-only functions until #900/#901) → its changed lines are `unrun`, never skipped; a changed `.md`/`.json`/`.astro` file → `.astro` is unmeasured and the others are not judged; `judged` counts the changed lines that had a statement (liveness, via `searched(...)`).
  - `render`: lists findings grouped by file with line numbers; says `0 unrun, 0 unmeasured of N judged` when clean.
- [ ] **Step 2:** FAIL. **Step 3:** Implement. **Step 4:** PASS.
- [ ] **Step 5:** Integration test (CI): temporary repo, a base commit, a change with one covered and one uncovered line plus a stand-in merged report and `tree.txt` → `--report-only` prints both and exits 0; a stale `tree.txt` → exit 2 `stale`; no report → exit 2 `missing`; without `--report-only` → exit 1.
- [ ] **Step 6:** Mutations: treat absent files as run → unmeasured test red; ignore `b` → branch test red; drop the stale check → integration red. Commit.
